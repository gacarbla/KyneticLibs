# Kynetic 0.2.0

First public release of the Kynetic framework: a TypeScript-native UI runtime with signals,
a JSX compiler, typed routing, i18n, forms, server rendering and a component kit.

## Packages

| Package | Version | Summary |
| --- | --- | --- |
| `@kyneticweb/reactive` | 0.2.0 | Signals, computed values, effects, batching and ownership. |
| `@kyneticweb/dom` | 0.2.0 | Fine-grained DOM renderer, context, lists, conditionals, portals and hydration. |
| `@kyneticweb/compiler` | 0.2.0 | Babel and Vite plugin that turns dynamic JSX expressions into thunks. |

## Highlights

- **Fine-grained updates**: components run once; signals update only the text, attribute or
  row that read them.
- **Compiler**: dynamic expressions become thunks automatically, including inside attributes
  and component children.
- **Lists and conditionals**: keyed `<For>` with per-row owners and in-place item proxies;
  `<Show>` mounts only the active branch.
- **SSR and streaming**: `renderToString`, `renderToStringAsync` with pending boundaries, and
  `renderToStream` in order or out of order.
- **Hydration**: elements, dynamic bindings, context, events, refs, keyed lists and
  conditionals are adopted in place.
- **Router**: path, hash and memory strategies, typed params, guards, lazy routes and
  `preload()` before hydration.
- **UI kit**: buttons, inputs, selects with search and groups, checkboxes, radios, switches,
  sliders, badges, avatars, alerts, progress, tabs, menus, tables and dialogs, with
  `size`, `tone` and `variant` parameters.
- **Testing and devtools**: DOM testing helpers and a live component/statistics panel.

## Install

```bash
npm install @kyneticweb/reactive @kyneticweb/dom @kyneticweb/compiler
```

The runtime is ESM-only and requires Node 20+ for SSR and tooling. The examples show the
complete setup:

- `examples/counter`: runtime, compiler and UI kit.
- `examples/kit`: 14-category component gallery.
- `examples/ssr`: server rendering, streaming and hydration with router, i18n and forms.

## Known limitations

- Portals, error boundaries and pending boundaries are not hydrated in place; they fall back
  to a client render of the root.
- Client-side Suspense and transitions are not implemented yet.
- The UI dialog moves and restores focus but does not trap it.
- Devtools does not register components that were hydrated (it tracks components created
  after the panel is mounted).
- `For` is reactive at the top level of each item; nested mutations need a new object or an
  accessor.

## Compatibility

- Node 20, 22 and 24 are tested in CI.
- Browsers with ES2022 and native ESM.
- TypeScript 5.9 or newer for the compiler types.
